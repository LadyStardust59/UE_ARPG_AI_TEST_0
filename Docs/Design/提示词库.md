# 提示词库 · 10 组可直接复制的提示词
## 配套《AI协作开发工作流方案.md》

**使用前必读（3 条）**

1. **方括号 `[...]` 里是你要替换的内容**，其余原样复制。
2. **`[CONTRACT PACK 片段]` 处必须粘贴真实的 YAML 片段**（从 `Docs/CombatGDD.yaml` 与 `Config/AI/*.yaml` 里取），不要写"见附件"——AI 读不到你的文件系统。
3. **每条提示词末尾的"证据要求"不要删**。删了它，你就失去了判断 AI 是否真的做完的唯一手段。

**通用替换变量**

| 变量 | 含义 | 示例 |
|---|---|---|
| `[PROJECT]` | 项目名 | `QiSanShen` |
| `[MANNEQUIN]` | 骨架资产路径 | `/Game/Characters/Mannequin/SK_Mannequin` |
| `[BASE_CLASS]` | 战斗角色基类 | `AAM_CombatCharacter` |
| `[CONTRACT PACK 片段]` | 相关 YAML 片段原文 | 见方案 §2.1 |

```
  Docs/ Config/AI/ Tools/ Tests/ Content/

【3 契约注入】
人读设计文档的关键章节（原文粘贴）：
[粘贴《战斗系统设计文档》第 2~5 章]

【4 硬约束】
- 不得发明设计文档中不存在的机制或数值；文档没写的，标注 `TODO: 待定` 而不是填默认值。

【7 证据要求】
附：(a) 4 个文件的完整内容；(b) 一份 `validate_gdd.py` 脚本，能检查上述验收标准
并在违反时以非零码退出；(c) 运行该脚本的输出。

【8 自检与回滚】
如设计文档中存在互相矛盾的数值，不要自行选择，全部列出并停止等待确认。
```
